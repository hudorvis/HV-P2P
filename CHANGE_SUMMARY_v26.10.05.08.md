# HV P2P v26.10.05.08 change summary

Date: 2026-10-05

Authoritative lineage: `HV P2P v26.10.05.07 - GitHub Ready Source.zip` -> this native-build carrier hotfix.

## Why `.05.08` exists

GitHub Actions successfully entered the v26.10.05.07 native firmware build and compiled the CTRL-TS far enough to emit only normal library/source warnings, but the build then failed while compiling the staged CTRL carrier. The supplied Actions excerpt ends with `arduino-cli ... HV_P2P_CTRL_EDGEBOX_v26.10.05.07` returning exit status 1 and does not contain the lower-level compiler/linker diagnostic.

The failure boundary is important: CTRL is compiled only after the freshly compiled CTRL-TS `.ino.bin` has been converted into `HV_P2P_CTRL_TS_Firmware_Image.h`. In `.05.07` that helper represented the complete multi-megabyte firmware image as a comma-separated C integer initializer inside a header included by the main CTRL sketch. That representation is unnecessarily expensive for the C++ compiler to parse and retain as AST data, and becomes increasingly fragile as the CTRL-TS image grows.

## Native carrier build fix

v26.10.05.08 preserves the exact same carrier bytes, SHA-256 identity and RS485 updater protocol, but changes only their build-time representation:

- `HV_P2P_CTRL_TS_Firmware_Image.h` is now a small generated metadata/declaration header.
- The exact native touchscreen image is emitted into a sibling generated `HV_P2P_CTRL_TS_Firmware_Image.cpp` translation unit as concatenated escaped byte-string literals.
- CTRL still references `HV_CTRL_TS_IMAGE` and `HV_CTRL_TS_IMAGE_SIZE` exactly as before; no firmware transfer framing or verification semantics change.
- The generated carrier includes a compile-time size assertion, while `verify_staged_hmi_header.py` reconstructs the generated bytes and verifies byte identity plus SHA-256 against the native CTRL-TS `.bin` before CTRL compilation.
- `native_build_firmware.py` now refuses an unexpectedly large metadata header or a missing external carrier source and reports carrier/native-image sizes before the CTRL build.
- A new `test_native_carrier_compile_0508.py` regression generates and host-compiles a 1 MiB carrier on every source audit. A separate release stress check exercised the full `0x380000` / 3.5 MiB CTRL-TS slot successfully.

This removes the compiler-heavy bulk integer initializer without changing the image that CTRL sends to CTRL-TS.

## `.05.07` functionality preserved

All requested `.05.07` fixes remain present and unchanged in `.05.08`:

- post-update CTRL-TS success requires a new boot identity plus exact target version/SHA rather than merely a REBOOT ACK;
- CTRL-TS Near/Far/REF/ramp/preset geometry is rebalanced without reducing the minimum font size;
- SRVR Settings -> CTRL-TS uses the `Link` subheading;
- uncaptured calibration fields use ASCII `-`;
- CTRL-TS Joystick and Limit Calibration include Cancel;
- Limit Calibration is transactional and commits Near/Far/Ref/motor-direction changes only at the final Ref capture;
- malformed/incomplete W1P STATUS frames are rejected without erasing the previous valid safety snapshot;
- PONG does not invalidate W1P STATUS authority;
- `SRVR_ALIVE` is transmitted by a background worker so CTRL liveness does not depend on macOS Qt foreground scheduling;
- non-zero W1P VEL refresh has a short background producer lease that bridges brief Qt scheduling stalls while preserving the independent 500 ms W1P watchdog;
- the joystick-neutral re-arm interlock remains intact after genuine safety interruptions.

## Safety/architecture unchanged

W1P's independent 500 ms VEL freshness watchdog is unchanged. AI0 E-stop / AI1 joystick mapping, hard-limit protection, predictive/dynamic soft limits, Leadshine velocity architecture, CTRL↔CTRL-TS single-flight/event ACK behavior, positive operator Current Speed presentation with signed wire velocity, and CTRL -> W1P -> CTRL-TS update ordering remain unchanged.

## Verification status

The source/static/regression/preflight suite passes in the source-audit environment, with PySide6-only runtime tests remaining a desktop CI gate. The new carrier generator was also stress-tested at the complete 3.5 MiB touchscreen OTA-slot size and verified byte-for-byte before host compilation.

GitHub Actions remains authoritative for ESP32 native compilation and frozen desktop builds. No local firmware binaries are supplied or represented as authoritative.
