# HV P2P v26.10.06.05 deep code audit

Date: 2026-10-06

## Locked baseline

`v26.10.06.04` is the locked production baseline. The production diff is restricted to CTRL-TS confirmation handling and SRVR canonical status presentation. CTRL and W1P firmware logic, QML layout, firmware authority and update coordinator logic are unchanged apart from release identity.

## Calibration confirmation audit

The touchscreen confirmation state is local (`selected_aux` -> `confirmed_aux`) and commands are delivered through the existing retry-safe EVENT queue. The inconsistent one-press symptom was caused by a second input path: `apply_flags_to_aux()` treated rising A7 AUX flag bits returned by CTRL as another confirmation press. In the current EdgeBox design those AUX bits are generated by the touchscreen command itself, not a separate physical AUX contact. A sufficiently delayed status echo could arrive after the wizard advanced and pre-select the next step.

The fix removes returned AUX flags from local confirmation semantics. Step/kind changes also clear both selection states. Joystick, Limit and Winch calibration therefore use exactly the same two-fresh-click rule at every step.

## Rapid touch audit

The previous `AUX_TOUCH_CONFIRM_GAP_MS = 250` was enforced when queued events were consumed. It was therefore possible for two distinct fast clicks to be timestamped effectively together by the consumer and for the second to be ignored. `.06.05` debounces duplicate LVGL callbacks at the producer with a 35 ms threshold, but places no processing-time delay between two distinct queued clicks.

## Status arbitration audit

`_resolved_system_status()` remains the one authority consumed by the SRVR UI and transmitted to CTRL/CTRL-TS. New endpoint/ramp states are evaluated only after all existing red and service/calibration/uncalibrated states. Near/Far use a 1.0 m window around the calibrated endpoints. Ramping uses the existing ramp geometry and signed line motion, and is reported only while travelling toward the endpoint whose ramp zone contains the skate.

The new status function does not write position, limits, ramp values, velocity commands or safety state. It is presentation-only.
