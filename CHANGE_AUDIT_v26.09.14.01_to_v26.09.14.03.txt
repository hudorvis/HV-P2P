HV P2P CHANGE AUDIT — v26.09.14.01 -> v26.09.14.03
================================================

Reason for revision
-------------------
GitHub Actions compiled CTRL-TS successfully, staged and verified the exact CTRL-TS image, then failed compiling CTRL because Arduino ESP32 core 3.3.8 includes Print.h, which defines the macro `HEX` as 16. The shared SRVR authority header declared `static const char* HEX`, so preprocessing changed the identifier and caused a C++ compile error. The identical header in W1P would have failed for the same reason.

Corrective change
-----------------
- Renamed the local SHA-256 hexadecimal lookup symbol from `HEX` to `HEX_DIGITS` in the byte-identical CTRL/W1P `HV_P2P_SRVR_Authority_OTA.h` headers.
- No firmware-authority behavior, safety gate, protocol, timing, UI, motion-control behavior or endpoint was changed.
- Added a source regression assertion that fails if the shared authority header reintroduces a `static const char* HEX` declaration and confirms the safe lookup name is present.
- Bumped all active release/build identities and GitHub artifact names to v26.09.14.03.

Preservation
------------
The approved Run and Setup QML byte hashes remain unchanged. W1P's independent 650 ms VEL watchdog, stopped/braked OTA service gate, Servo Enable inhibition, brake/E-stop/RS485 protections, rollback/recovery behavior, Speed/DYNAMIC behavior, Power/TRADITIONAL behavior, CTRL-before-CTRL-TS sequencing, no-auto-downgrade policy, and prior Windows x64 CI hardening are preserved.

Native build evidence
---------------------
The triggering GitHub run proved CTRL-TS native compilation and CTRL-TS staging/header verification succeed under the pinned toolchain before the CTRL macro collision. This source package does not fabricate native binaries locally; GitHub Actions remains the authoritative native compile gate.
