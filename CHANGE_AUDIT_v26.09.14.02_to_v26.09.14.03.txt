HV P2P CHANGE AUDIT — v26.09.14.02 -> v26.09.14.03
================================================

Triggering GitHub evidence
--------------------------
The macOS Intel, macOS Apple Silicon and Windows x64 jobs all imported backend.py
successfully and then failed at the same assertion in tools/test_backend_logic.py:
"Not Calibrated incorrectly triggered E-stop".

Root cause
----------
v26.09.14.02 intentionally changed missing W1P FW_MATCH to fail closed. The old
backend regression fixture still supplied a legacy STATUS packet with no FW_MATCH
and later expected a healthy motion state. Runtime behavior was correct; the test
fixture contradicted the new authority contract.

Corrective test change
----------------------
- Healthy W1P STATUS fixtures now include FW_MATCH=1 and FW_AUTH=matched.
- Healthy fixtures include the complete RS485/feedback-good field set so the
  firmware-authority assertion is isolated from feedback-state failures.
- A separate assertion proves missing FW_MATCH remains fail closed.

Additional deep-audit safety findings/fixes
-------------------------------------------
1. Generic W1P peer traffic (HELLO/PONG/HMI diagnostics) can refresh peer presence,
   but must not revive a prior session's firmware-authority/RS485-good state.
   SRVR now tracks full STATUS freshness separately and invalidates prior health on
   HELLO.
2. STATUS freshness was previously marked before all fields were parsed. A malformed
   numeric field could abort parsing after stale state had partially survived. Every
   STATUS is now treated as a fail-closed safety transaction: prior authority/RS485
   health is invalidated first, and freshness is committed only after successful
   safety-critical parsing.
3. Motion safety and the RS485-ready property now require a fresh full W1P STATUS,
   not just recent generic peer traffic.

CI hardening
------------
- Added tools/test_backend_logic_headless.py to run the complete backend logic suite
  without a PySide6 installation; native desktop jobs still run it with real PySide6.
- Moved the master source/backend/protocol suite to the beginning of build-firmware,
  before Arduino setup/native compilation.
- Added tools/test_release_consistency.py to reject mixed active revision paths.

Preservation proof
------------------
Run and Setup QML remain byte-identical to the approved baseline. W1P reviewed
safety/authority function hashes remain locked, including the independent 650 ms VEL
watchdog and hvPrepareSafeServiceState stopped/braked OTA gate. Speed/DYNAMIC and
Power/TRADITIONAL behavior are unchanged. The v26.09.14.02 Arduino HEX_DIGITS fix,
no-auto-downgrade policy and all previous Windows x64 CI hardening are retained.
